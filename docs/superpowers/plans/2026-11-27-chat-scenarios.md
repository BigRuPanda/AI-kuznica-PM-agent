# Готовые сценарии в переписках — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** В личной и групповой переписке продакт выбирает один из пяти сценариев, уточняет текст и отправляет его агенту.

**Architecture:** Каталог и правила переключения черновиков живут в клиенте. Компонент переписки владеет текстом и фокусом, меню передаёт в него выбранный сценарий. Отправку, историю, вложения и ответ агента обслуживает текущая форма.

**Tech Stack:** React, TypeScript, sessionStorage, Node.js 24, Playwright.

**Spec:** [Утверждённые тексты и поведение](../specs/2026-11-27-chat-scenarios-design.md).

## Global Constraints

- Пять названий и пять промптов взять дословно из таблицы спецификации, в указанном порядке.
- Кнопка «Сценарии» доступна на странице переписок и в пустом, и в начатом чате. Сервер получает обычный текст только при отправке пользователем.
- Шаблон и собственное уточнение разделяет одна пустая строка. Черновик принадлежит паре пользователь–переписка.

## Review Focus

1. После трёх переключений произвольный пользовательский текст присутствует один раз.
2. Переписанное внутри шаблона предложение сохраняется целиком. Повторный выбор текущего сценария сохраняет редакцию.
3. Черновик старого формата, перезагрузка и смена переписки сохраняют текст нужного пользователя.
4. На мобильном экране и с клавиатуры доступны все пять пунктов. Escape возвращает фокус к кнопке, выбор — в конец поля.
5. Приложенный материал или выделение доходит до обычной отправки. Открытие, выбор и отмена сами по себе не запускают поручение.

### Задача 1. Каталог и переключение черновика

**Файлы:** создать `web/chat-scenarios.ts` и `tests/chat-scenarios.test.mjs`.

**Интерфейс:** экспортировать `chatScenarios` с устойчивыми идентификаторами и полями `id`, `label`, `prompt`. Тип `ScenarioDraft` содержит `text: string` и `scenarioId: string | null`. Функция `selectScenario(draft: ScenarioDraft, scenarioId: string): ScenarioDraft` возвращает следующий черновик. Кодировку хранилища проверяют `loadScenarioDraft(stored: string | null, pendingText: string): ScenarioDraft` и `serializeScenarioDraft(draft: ScenarioDraft): string`.

- [ ] Написать тесты на пустое поле, все пять утверждённых текстов, смену сценария с уточнением, правку внутри шаблона, повторный выбор и полностью очищенное поле. Для трёх переключений итог должен быть равен `последнийПромпт + '\n\nТолько Kaspersky, мобильные, октябрь'`.
- [ ] Добавить проверки восстановления исходной строки старого формата и нового черновика с активным сценарием. Если сохранённой записи нет, вернуть текст незавершённой отправки.
- [ ] Запустить `node --test tests/chat-scenarios.test.mjs` и убедиться, что тест падает из-за отсутствующей реализации.
- [ ] Реализовать каталог и переходы. Снимать только точный префикс предыдущего вставленного шаблона, сохраняя собственный текст пользователя. При несовпадении префикса сохранять весь отредактированный черновик. Новый формат хранения должен однозначно отличаться от обычного текста старого черновика.
- [ ] Повторить тест, выполнить `pnpm build` и зафиксировать каталог с тестами отдельным коммитом.

### Задача 2. Меню в работающей переписке

**Файлы:** создать `web/chat-scenario-menu.tsx`, изменить `web/team.tsx`, `web/chat.css` и `tests/workspace.browser.mjs`.

**Интерфейс:** `ChatScenarioMenu({ onSelect }: { onSelect: (scenarioId: string) => void })` отвечает за открытие и закрытие меню. В `Chat` на странице `ChatWorkspace` обработчик выбора применяет `selectScenario`, затем фокусирует textarea и ставит курсор в конец. Чтение и запись используют существующий ключ `pm-chat-draft/<userId>/<threadId>`.

- [ ] Добавить браузерный сценарий на штатной фикстуре. В личном чате проверить пять подписей, уточнение после нескольких переключений, повторное открытие чата и отправку отредактированного текста одним запросом `ask`. До отправки счётчики запросов `ask` и `say` должны оставаться нулевыми.
- [ ] В групповом чате проверить клавиатурный выбор и Escape, позицию курсора и сохранение прикреплённого материала или выделения. На ширине 390 пикселей проверить доступность всех пунктов и отсутствие горизонтального переполнения. Проверить изоляцию группового черновика между двумя участниками.
- [ ] Выполнить `pnpm build`, затем `node --test tests/workspace.browser.mjs`. Убедиться, что новая проверка падает при поиске кнопки «Сценарии».
- [ ] Встроить меню рядом с вводом сообщения. Использовать доступные кнопки и принятую в `web/chat-menu.tsx` работу со всплывающим меню. При очистке поля, успешной отправке или замене текста старой подсказкой снять отметку о выбранном сценарии. При ошибке отправки сохранить редакцию. Существующие поля запроса и явный выбор получателя в групповой беседе сохраняются.
- [ ] Прогнать `pnpm test` и `pnpm test:ui`. Проверить успешное завершение обоих наборов и зафиксировать интерфейс с браузерными тестами отдельным коммитом.
