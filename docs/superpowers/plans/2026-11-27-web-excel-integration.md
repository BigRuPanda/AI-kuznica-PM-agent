# План интеграции веб-поиска и Excel-источников

**Цель.** ПМ может задать вопрос по загруженной книге, найти публичные источники через Яндекс и проверить утверждение по конкретной странице из чата или ячейки. Из ответа открываются исходная версия книги, нужная ячейка и использованная веб-страница.

**Подход.** Переносить возможности отдельными изменениями поверх актуального `main`. Для импорта, расчётов, прав доступа, профилей передачи данных и очереди поручений использовать реализации основной ветки. План предназначен для поэтапной реализации на Node.js, SQLite, Python и React. Все пункты ниже относятся к предстоящей работе.

На этой ревизии прогнаны `web-search`, `source-policy`, `materials` и `release-decision`. Прошли 25 тестов, два сценария пропущены из-за отсутствия ZIP организатора в тестовом окружении. Сетевые ответы поиска и продавцов моделировались. Отдельная XLSX с внешней гиперссылкой и видимой подписью подтвердила, что импортёр извлёк предложение и цены, сохранил подпись и потерял целевой URL. Маршрут общего поиска читает выдачу Яндекса, а прямое чтение HTML вызывается из проверки поддерживаемого продавца.

### Работы и условия приёмки

#### 1. Зафиксировать поведение основной ветки

- [ ] Перед началом реализации сверить вершины GitHub и локальных веток. Создать рабочую ветку от согласованной актуальной main. Если сценарии чата к этому моменту ещё разрабатываются отдельно, проверить совместимость с их последней ревизией до объединения изменений в `web/team.tsx`.
- [ ] Запустить на базе `pnpm test`, `pnpm build`, `pnpm test:ui`. Зафиксировать исходные результаты локального пилота по [существующему протоколу](../../../submission/pilot.md). Для проверки обновления подготовить изолированную копию базы со старыми версиями книг, ссылкой на ячейку, незавершённым расследованием и планом наблюдения.
- [ ] Сохранить обработку `watch.version = 2` из `server/watch-measurement.mjs`. У донора тот же номер обозначает другую структуру. Для получения строки Excel или карточки продавца достаточно вынести операции чтения из `server/knowledge.mjs` и `server/release-decision.mjs`. Подстановка всего механизма наблюдений донора затрагивает уже сохранённые планы.

#### 2. Открывать строку Excel и сохранять адрес гиперссылки

- [ ] Расширить `scripts/office_import.py` поверх основной версии. В разрешённых рабочих листах извлекать URL из текстовой ячейки и из стандартной внешней XLSX-гиперссылки с подписью. Связывать адрес с точной ячейкой, листом и версией документа. Для строки с несколькими ссылками показывать выбор. Для архивов сохранить вложенные пути, а для дат использовать календарь конкретной книги.
- [ ] Добавить в `server/workspace-operations.mjs` операции `knowledge-sources`, `knowledge-source({version, loc, offset})` и `source_value`; адаптировать просмотрщик `web/knowledge-source.tsx`. Для неоднозначной метрики различать источник, определение, периодичность и сегмент по правилам main. Ссылку выдержки на оригинал и адрес самой выдержки показывать с соответствующими подписями.
- [ ] В `tests/research-workbooks.py` и `tests/research-search.test.mjs` добавить книгу с подписью «Карточка продавца» и отдельным URL, две одноимённые книги в разных папках и дату в календаре 1904. Проверить связь URL с ячейкой, две разные версии источников и верную дату. Для старого документа с утраченной целью показать книгу, которую требуется загрузить повторно.

#### 3. Перенести поиск по архиву и переиндексацию

- [ ] Адаптировать `server/archive-search.mjs`, `server/research-search.mjs`, `server/evidence.mjs` и офисный импортёр. Добавить связанные ответы одной строки интервью, цены конкурента и Store, поиск по справочнику, задачам и релизам. Сохранить полнотекстовый поиск main, фильтр на дату, исключения ПМ и связь «подтверждает / опровергает». Включать в общий ответ только данные, доступные в данном пространстве.
- [ ] Для интервью применять правила обезличивания до сохранения текста и ссылок. Контактные столбцы, ссылки на записи интервью, расшифровки и учётные данные исключить и из веб-проверки. Для цен рассчитывать разницу из сопоставимых строк. Помечать пропуск в цене или дате как отсутствие данных.
- [ ] Адаптировать обновление индекса из `server/source-policy.mjs` и `scripts/ops.mjs` к транзакциям импорта main. Повтор исходного ZIP обновляет только всё ещё действующие документы. Более свежая согласованная книга сохраняет приоритет, предыдущие ссылки открывают прежние значения. Повторный запуск не создаёт новых уведомлений или повторных записей. Этот переход нужен и для уже загруженных цен, в которых отсутствует `comparison`.
- [ ] Перенести проверки из `tests/source-policy.test.mjs` и дополнить тестами main. В ответе про респондента из строки 3 должны быть только ссылки на строку 3. Короткая точная запись должна обойти длинную сводку. После повторного импорта проверить старую ссылку, активную версию, отсутствие удалённой строки в текущей выдаче и сохранение поправки ПМ.

#### 4. Сохранить доказательства в ответах про даты, релизы и задачи

- [ ] В `server/archive-search.mjs`, `server/day-comparison.mjs`, `server/workbench.mjs` и `server/workspace-agent.mjs` привязать ответы к выбранным датам и ряду main. Выдавать значения с единицами, вычисленную разность и ссылки на исходные строки. Для календарного объяснения нужны совпадение даты и затронутой метрики. Отмечать причинность как гипотезу.
- [ ] Извлекать ID задач из календаря релизов и обратную связь из бэклога. При уточнении «какая задача у этого релиза?» учитывать выбранный релиз и проверять доступ к разбору. Для неизвестного релиза запрашивать уточнение. Ссылки на ячейки бэклога и календаря должны открываться из ответа.
- [ ] Перенести лимиты вызовов в `server/agent.mjs` и `server/gemini.mjs` с сохранением профилей main и Qwen/ProxyAPI. У донора архивная сводка ограничена 42 секундами и 220 токенами, бюджет многошагового ответа — 90 секунд. Текст интервью, измерения и ID связанных задач отдавать непосредственно по источникам. При таймауте или появлении в сводке постороннего числа вернуть исходные записи и дать продолжить прерванное поручение.
- [ ] В `tests/source-policy.test.mjs` и `tests/materials.test.mjs` проверить два числа за две даты, событие с чужой метрикой в тот же день, обе стороны связи задачи и релиза, пропуск наблюдения, ответ с выдуманным числом и возобновление после таймаута.

#### 5. Подключить поиск Яндекса и проверку продавцов

- [ ] Перенести `server/web-search.mjs`, `server/competitor-check.mjs` и `scripts/web_evidence.py`. В чате различать явный веб-поиск, открытие конкретного URL и проверку цены продавца. Применять существующую политику сети из `server/data-profile.mjs`. Поиск передаёт Яндексу только текст поискового запроса. Явный отказ пользователя от поиска действует и при включённом переключателе.
- [ ] Перенести подтверждение цены по артикулу, редакции, сроку, количеству и единице продажи. Если подходят две строки, сначала показать их для выбора. Хранить исходную цену Excel отдельно от результата веб-проверки с URL и временем. При показе истории использовать сохранённые данные соответствующей проверки.
- [ ] В `.env.example` и `README.md` описать ключ и каталог Yandex Search, использование Python и поведение при отсутствии ключа. В `scripts/ops.mjs` учесть фактические платные поисковые запросы отдельно от вызовов модели и повторов из кеша. В `tests/web-search.test.mjs` проверить отказ от сети в локальном профиле, поиск без модели, пустую выдачу, исчерпанную квоту и несовпадающий артикул.

#### 6. Добавить чтение публичной страницы по URL

- [ ] Предлагаемый объём первого выпуска — публичные HTML-страницы по HTTP(S), которые можно прочитать без входа. Новый модуль `server/public-page.mjs` получает адрес и возвращает исходный и конечный URL, заголовок, время чтения, извлечённый текст либо причину недоступности. Проверять публичность назначения и правила профиля при соединении и при каждом перенаправлении. Ограничить время и объём чтения, обращаться без пользовательских cookies и секретов интеграций.
- [ ] Зарегистрировать операцию `read_public_page` в `server/workspace-operations.mjs`. Для сообщения принять явно указанный URL; для ячейки разрешать адрес на сервере по версии и координате в доступном документе. Использовать текст страницы как недоверенный источник. К выводу приложить ссылку и короткий подтверждающий фрагмент. При недостатке свидетельств сообщать об этом. Для закрытой страницы и неподдерживаемого формата вернуть точную причину.
- [ ] В `tests/public-page.test.mjs` проверить прямой публичный URL, ссылку из ячейки, разрешённый редирект, запрещённое назначение после редиректа, недоступную страницу, ответ без нужного утверждения и запрет сети в локальном профиле. Проверка должна различать страницы с одинаковым заголовком и разными утверждениями. Вызовы выполнять через подставной транспорт и управляемое разрешение адресов.

#### 7. Соединить результаты в чате и проверить обновление

- [ ] В `server/workbench.mjs`, `server/workspace-agent.mjs` и `web/team.tsx` сохранить контекст выделенного диапазона и версии книги при веб-проверке. Возвращать отдельно строку Excel, фрагмент выдачи и прочитанную страницу. Для каждого маркера цитирования должен существовать реальный источник ответа. Повтор поручения использует уже сохранённые шаги. Для веб-проверок в фоновых расследованиях применять тот же профиль и учитывать данное пользователем разрешение на внешний поиск.
- [ ] В `server/team-mcp.mjs` и форматтере Telegram в `server/materials.mjs` передавать ссылки на прочитанную страницу и доступную ячейку. В личном и командном чатах проверить права двух пользователей, изоляцию черновиков и выбор каждого из пяти готовых сценариев. Выбор пункта меню сам по себе запрос не отправляет.
- [ ] Сквозной пример для `tests/workspace.browser.mjs`: пользователь выбирает строку с ценой, просит сверить конкретное утверждение на сайте и получает обе ссылки, дату чтения и результат сверки. Отключение интернета по-прежнему позволяет открыть исходную строку. Дополнительно проверить веб-вопрос из пустого чата без привязанного кейса.
- [ ] Повторить базовые команды из пункта 1 и `pnpm pilot:accept` на настроенном изолированном пилоте. После обновления копии базы открыть прежний материал, завершить начатое расследование, пересчитать существующий план наблюдения и пройти подтверждение черновика Redmine. Зафиксировать отдельно результаты с официальным ZIP и реальными внешними сервисами, когда эти источники доступны.

### Границы переноса

Проверка продавцов использует сведения из релизов и цен, поэтому переносим нужные операции чтения. Внедрение всего Signal Bridge, изменение доставки личных уведомлений, автоматическая публикация страниц после закрытия Redmine и замена экрана решений по релизу требуют отдельного решения. Существующие сценарии этих подсистем остаются частью регрессионной проверки.
