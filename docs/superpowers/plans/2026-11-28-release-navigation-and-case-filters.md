# Навигация по релизам и фильтры разборов — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal**

Открывать оценку напрямую из журнала и находить связанные разборы по типу.

**Architecture**

Журнал использует признак `decisionAvailable` и передаёт идентификатор в существующий маршрут оценки. Список разборов использует имеющиеся поля сигнала и релиза для меток и фильтрации.

**Tech Stack**

React, TypeScript, esbuild, Node.js, Playwright.

**Spec** — [Навигация по релизам и фильтры разборов](../specs/2026-11-28-release-navigation-and-case-filters-design.md)

## Global Constraints

- Название страницы «Оценка релиза», кнопка «Запланировать оценку», метки «сигнал» и «релиз».
- Фильтр типа «Все», «Сигналы», «Релизы», «Самостоятельные» работает вместе с фильтром «Состояние».
- Работать с актуальным состоянием `main-copy-2026-11-28`. Запрашивать разрешение на пуш после завершения и проверки.

## Review Focus

- Запись без оценки ведёт из прежней ссылки в журнал, где доступно планирование.
- Прежняя ссылка на оцениваемый релиз открывает именно его.
- На узком экране кнопка планирования помещается вместе с длинной строкой.
- У разбора с привязкой через сигнал видны обе метки, и он входит в обе группы.
- Фильтры типа и состояния могут дать пустую выборку и показывают её причину.
