# Signal Bridge

Модуль для разработчика UI и агента Softline Signal. Он получает отчёт Яндекс Метрики, прикладывает факты к подтверждённой задаче Redmine и отправляет сообщения в Telegram при закрытии отслеживаемой задачи и при падении метрики. Для этих операций достаточно REST API и SQLite. Отдельный вызов модели не требуется.

## Запуск на Windows

1. В архиве для Windows x64 есть Python. При запуске из Git установите Python 3.11+ с командой py -3. Для собственного демостенда запустите Docker с Linux-контейнерами, затем `setup-redmine.cmd`. Скрипт поднимет официальный Redmine 6.1, заведёт закрытый проект `signal-demo` и отдельного пользователя проекта. Откройте `http://127.0.0.1:18881/projects/signal-demo`. Реквизиты входа показывает `demo-login.cmd`. Данные остаются в именованных томах Docker.
2. Откройте `configure.cmd` и введите OAuth-токен Метрики с правом `metrika:read`. Укажите номер своего счётчика и пять ID целей витрины по порядку. Если используете корпоративный Redmine, укажите его адрес, идентификатор проекта и API-ключ пользователя с правами чтения и создания задач. Администратор проекта должен включить REST API. Внешний Redmine можно использовать без Docker. Пользователю, закрывающему задачу, нужны права соответствующего перехода.
3. Для уведомлений в личный чат создайте бота командой `/newbot` у [BotFather](https://t.me/BotFather). Откройте `connect-telegram.cmd`, введите токен скрытым вводом, перейдите по выданной ссылке и нажмите «Старт» в своём Telegram. Ссылка связывает конкретный личный чат с этим экземпляром модуля. Для группы задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` через окружение и добавьте бота в нужную группу с правом писать.
4. Запустите `start.cmd`. Откройте `http://127.0.0.1:18880/health`. Поле `configured` показывает наличие настроек, `jobs` — время и ошибки фактических проверок, `queue` — состояния отправки. При повторном запуске используются те же база и настройки. На Linux/macOS используйте системный Python 3.11+ и команды `python3 setup_demo.py`, `python3 configure.py`, `python3 connect_telegram.py`, `python3 service.py`.

Для передачи копируйте чистый архив. Каталог `.local` содержит личные настройки и состояние конкретной установки. В Windows настройки защищены DPAPI текущего пользователя, в POSIX сохраняются в файле с правами 0600. Переменные окружения имеют приоритет. Через `SIGNAL_BRIDGE_STATE` можно задать отдельный путь. На новом компьютере владелец вводит свои ключи. Фоновый опрос выполняется, пока запущен `service.py` и компьютер подключён к сети. Для постоянного пилота потребуется постоянно работающий хост.

## Командный сайт

Ветка проекта включает готовое подключение к разделу «Задачи и документация». Запустите Bridge и веб-сервер на одном компьютере. В корневом `.env` сайта укажите:

```dotenv
SIGNAL_BRIDGE_URL=http://127.0.0.1:18880
SMTP_HOST=127.0.0.1
SMTP_PORT=18883
SMTP_TLS=local-test
SMTP_FROM=signal@example.invalid
TELEGRAM_BOT_TOKEN=
TELEGRAM_BIND_POLLING=true
```

При `DATA_PROFILE=local` добавьте точный origin Bridge в `LOCAL_HTTP_ORIGINS` сайта. В Windows установите `PYTHON_BIN` в путь к Python, если команда `py` недоступна. Запустите сайт по инструкции в корневом README. Откройте его под командным аккаунтом.

Укажите токен отдельного бота командного приложения в корневом `.env` сайта. Токен автономного бота и его чат настройте через `connect_telegram.py` или через `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в окружении процесса Bridge. Оба процесса используют собственную конфигурацию и хранят состояния доставки в отдельных базах. Фоновый опрос сайта рассчитан на одного потребителя обновлений бота без активного webhook. Для публичного HTTPS-стенда зарегистрируйте webhook на защищённый `POST /api/telegram`, передайте в Telegram тот же `secret_token`, который записан в `TELEGRAM_WEBHOOK_SECRET`, и выключите опрос.

1. В **Настройки → Мои уведомления** введите адрес и подтвердите восьмизначный код. На демостенде откройте [Mailpit](http://127.0.0.1:18882/). Срок действия кода — 10 минут. Для доставки во внешний ящик укажите SMTP-сервер организации, порт, отправителя и требуемые учётные данные с `SMTP_TLS=starttls` или `implicit`.
2. Нажмите **Привязать Telegram → Открыть бота в Telegram → Старт**. Сайт покажет статус «Личный чат подключён». Каждый участник привязывает свои контакты. Оба канала можно отключить по отдельности.
3. Откройте разбор, подготовьте черновик и подтвердите запись. Сайт запоминает снимок Метрики, использованный для задачи, и её номер в Redmine. При повторном подтверждении вернётся тот же номер.
4. После закрытия задачи сайт сохранит запись на версионированной странице базы знаний. Он приложит исходный отчёт и комментарий к закрытию, если участник оставил его в Redmine. В **База знаний → Оформить документацию** можно добавить вывод и версию Excel. После подтверждения обратная ссылка появится в журнале Redmine. При повторном открытии и новом закрытии обновится эта же страница. Фоновая проверка двух сервисов обычно занимает до двух минут плюс очередь доставки. Изменение бизнес-метрики после выкладки оценивается в отдельном разборе.

Администратор может настроить командный адрес Redmine: тогда приложение использует персональный ключ участника и сохраняет источник Метрики от Bridge. Внешнее пространство Confluence подключается в **Настройки → Подключения**. Пока адрес пуст, страницы доступны в самом приложении. Для локального просмотра с уже сохранённым отчётом запустите `service.py --cached-report`. В таком запуске фоновый опрос Метрики отключён.

На закрытом демостенде установите `REDMINE_REQUIRE_AI_FLAG=true` для сайта и Bridge. Подключите к трекерам проекта фильтруемое поле задачи типа «Логический» с именем «сгенерирована ИИ-помощником». Локальная настройка `setup_demo.py` добавляет его для проекта `signal-demo`. Bridge и персональное подключение отмечают новую задачу этим полем и проверяют значение при ответе Redmine. В обычных установках приложение ставит флаг, если он настроен в проекте. В закрытом локальном демо для прямого подключения задайте `REDMINE_DEMO_URL` с точным адресом HTTP сервера на loopback.

Штатная почта Redmine продолжает обслуживать наблюдателей по настройкам проекта. Личные подписки сайта обслуживает веб-сервер. Если пользователь подписан на один повод в обеих системах, он может получить два разных письма. Автономный Bridge оставляет веб-задачи с префиксом `web-draft-` веб-серверу для персональной доставки. Зарезервируйте этот префикс за сайтом.

Telegram служит демонстрационным каналом вместо DION. Встроенная база знаний хранит результаты на этом стенде. Согласование каналов с заказчиком и подключение к корпоративному SMTP относятся к пилоту. Корпоративные данные можно отправлять в Telegram после согласования с владельцем данных.

## HTTP API

Вызывайте HTTP с серверной стороны приложения. Сервис слушает loopback, порт 18880. Пример клиента находится в `example_client.py`. Если UI и Bridge запущены на разных компьютерах или в разных контейнерах, организуйте доступ через авторизованный backend. Открытая публикация порта в этой поставке не предусмотрена.

| Метод | Назначение |
|---|---|
| `GET /health` | Состояние конфигурации и фоновых операций |
| `POST /reports/refresh` с `{}` | Прочитать свежий отчёт из Метрики, проверить полноту, сохранить снимок |
| `GET /reports/latest`, `GET /reports/<id>` | Получить последний отчёт или конкретный снимок |
| `POST /tasks` | После подтверждения продактом опубликовать задачу в Redmine |
| `GET /issue-options`, `GET /tasks/<reference>/details` | Справочники проекта и карточка отслеживаемой задачи с журналом |
| `POST /tasks/<reference>/changes` | Подтверждённое изменение полей или комментарий с меткой операции |
| `GET /tasks/<reference>` | Получить номер, ссылку, последний проверенный статус и признак закрытия |
| `POST /sync` с `{}` | Сразу проверить состояния в Redmine и попытаться доставить уведомления |
| `GET /events` | Последние 100 событий с состоянием доставки, текстом и ID сообщения Telegram |
| `GET /closures?after=0` | До 100 сохранённых снимков закрытия по порядку. Передайте последний `seq` для следующей страницы |

Все POST принимают `Content-Type: application/json`. Для карточки берите исходный `id` из отчёта, показывайте продакту текст для подтверждения, затем отправляйте запрос:

```json
{
  "reference": "SIG-42",
  "report_id": "<id полученного отчёта>",
  "title": "Проверить регистрацию добавления в корзину",
  "description": "Сверить отправку события и повторить проверку на том же счётчике.",
  "confirmed": true
}
```

Ответ содержит `reference`, `report_id`, `redmine_id`, `url`, `status`, `closed`, `checked_at`. Внешний идентификатор `reference` задаёт вызывающая сторона один раз на карточку. Сохраните его до первой отправки. При повторе передавайте те же поля. Bridge возвращает существующий номер. При смене данных под тем же идентификатором возвращается ошибка. После потери ответа Redmine повторный запрос ищет прежнюю задачу по метке в описании. Если результат неизвестен, Bridge сообщает об этом и не повторяет создание вслепую.

Ошибки возвращаются как `{"error":"описание"}` с HTTP 400 для некорректного запроса или конфликта, 404 при неизвестном локальном ресурсе и 502 при ошибке внешнего API. При временной недоступности опрашивайте `/health`; в ответе `/sync` изучайте также `redmine.errors` и `telegram`.

## Что измеряется и когда приходит уведомление

Отчёт охватывает два последовательных полных семидневных окна до вчерашнего дня по Москве. В каждом массиве `periods` шесть чисел: все визиты, визиты с просмотром семейства, открытием подбора, показом результата, переходом на карточку лицензии и добавлением в корзину. Идентификаторы целей перечислены в `goals`. Визиты с `signal_qa=` в стартовом URL исключаются. Метрика для алерта — визиты с корзиной / все визиты. По умолчанию требуется минимум 20 визитов в каждом окне и снижение не менее чем на 20% относительно базы. Нулевой числитель в базе даёт статус «Мало данных». Пороги задают `SIGNAL_MIN_VISITS` и `SIGNAL_THRESHOLD`.

Метрика опрашивается каждые 15 минут, Redmine и очередь Telegram — примерно раз в минуту. Сбой одного внешнего сервиса отражается в `jobs`. При новом эпизоде снижения создаётся событие `metric_alert`. Эпизод завершается, когда достаточно данных и падение становится меньше порога. После восстановления следующее падение создаёт своё событие, даже если его отчёт совпадает с предыдущим. Для задачи, созданной через модуль, переход в статус с `is_closed=true` создаёт `issue_closed`. После повторного открытия и наблюдаемого нового закрытия приходит новое сообщение. По тексту виден конкретный статус Redmine, включая закрытие с отказом. Переходы, целиком прошедшие между двумя опросами, могут быть пропущены.

Telegram получает короткий текст. Для корпоративного Redmine добавляется ссылка на задачу. Если в демо доступен только localhost, номер остаётся в сообщении, а ссылка на компьютер разработчика опускается. Для маршрутизируемого адреса задайте `REDMINE_PUBLIC_URL`.

Событие остаётся `pending`, пока бот не привязан. После подтверждения Telegram оно получает `sent` и `message_id`. Это подтверждение со стороны API, а не отметка прочтения человеком. При ограничении частоты учитывается задержка Telegram. При обрыве после возможной отправки событие переходит в `uncertain`. Сверьте чат; для подтверждённо отсутствующего сообщения выполните `python delivery.py "<event_id>" --confirmed-absent`, для найденного — `python delivery.py "<event_id>" --observed-message-id 123`. Повторное обычное сканирование не дублирует подтверждённое сообщение.

## Проверка передачи

Из корня репозитория выполните `python integrations/signal-bridge/verify.py`, `py -3 integrations/signal-bridge/verify.py` в Windows или `python3 integrations/signal-bridge/verify.py` в Linux. Из каталога комплекта в Windows доступна команда `python.cmd verify.py`. Проверка использует временную базу и тестовые ответы внешних API. В `acceptance.json` сохранён протокол первоначального стенда от 26 ноября 2026 года.

Для своей сквозной проверки обновите отчёт, дважды отправьте один одобренный запрос с одним и тем же `reference`, закройте полученную задачу в Redmine и дважды вызовите `POST /sync`. Сверьте один номер Redmine, одно событие закрытия и его `message_id` в `GET /events`. Проверьте сообщение на телефоне.
