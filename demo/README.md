# Демонстрационные данные

Все записи и правила ниже приняты для прототипа. Файл `releases.csv` содержит момент включения функции для пользователей, `events.csv` — события компаний. Сборка воспроизводится командой `node demo/generate.mjs`. Время в файлах указано в UTC.

Для сравнения берём компании или счета за семь суток до включения и за семь суток после него. Начальная граница входит в период, конечная открывает следующий период. Для конверсии каждому наблюдению даём семь полных суток на оплату. В режиме «Данные на дату» доступны события до выбранного момента включительно. Для промежуточной конверсии берём только наблюдения с завершённым окном оплаты. Когда их ещё нет, показываем «Пока недостаточно данных».

| Показатель | Рабочее определение |
| --- | --- |
| Конверсия оформления в оплату | Среди компаний, начавших оформление, доля оплативших связанный заказ за семь суток от начала оформления. В демо у каждой компании одно оформление. Сегмент зафиксирован на момент оформления. |
| Сумма оплат | Сумма `amount_rub` по событиям `payment_received` за выбранный период. Поле `purchase_type` позволяет отдельно посмотреть покупки и продления. |
| Средний чек | Сумма оплат за период, делённая на число уникальных оплаченных заказов за тот же период. В демо каждый оплаченный заказ имеет одну полную оплату. |
| Доля своевременных продлений | Среди продлений со сроком `subscription_due` в периоде, уже наступившим на выбранную дату, доля с событием `subscription_renewed` к этому сроку включительно. В демо события одного продления связаны через `order_id`. |
| Оплата выставленных счетов за семь суток | Среди уникальных выставленных счетов доля оплаченных за семь суток от `invoice_issued`. По `invoice_page_viewed` и `ui_version` видно, какую версию страницы открывали. |

В R-001 конверсия по всем компаниям составляет 140/1000 до релиза и 110/1000 после. Для новых клиентов получаются 20/400 и 30/600, для постоянных — 120/600 и 80/400. Общий показатель меняется из-за состава аудитории.

В R-002 оплачено 80 из 200 счетов до релиза и 110 из 200 после. В каждом из двух клиентских сегментов доля выросла с 40/100 до 55/100. Это синтетическое сравнение периодов для проверки расчётов. Чтобы оценить причинный эффект кнопки на реальных данных, потребуется отдельно выбрать метод сравнения.

В R-002 после запуска первой показали новую страницу для 80 счетов (48 оплат за семь суток), старую — для 120 (62 оплаты). У 20 из этих 200 счетов зафиксирован просмотр обеих версий. Каждый из них входит в группу первой показанной версии один раз. В детализации можно проверить номер счёта и время первого просмотра каждой версии.

В R-001 версию формы определяем по началу оформления, в R-002 — по первому подтверждённому показу страницы конкретного счёта. Учитываем выбранный тип клиента и дату среза. Пометка «Видел обе версии» появляется после первого просмотра другой версии, если к этому моменту счёт ещё не был оплачен. Повторные открытия той же версии считаются одним просмотром для этой пометки. Записи без подтверждённой версии остаются в общем результате.
